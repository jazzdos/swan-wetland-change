## Description

A DuckDB glob over the bucket has to list it, but the public policy grants only s3:GetObject (infra/main.tf:29) and tests/test_infra.py forbids s3:ListBucket, so success criterion 3 cannot be met anonymously. The S3 variant of the query in README.md needs credentials for the same reason. The GDAL cross-reader test also skips everywhere because the pyogrio wheel has no Parquet driver. Verdict PLAUSIBLE: not tested against S3. Evidence: docs/research/2026-11-04-milestone-2-review.md L2.

## Acceptance Criteria

- [ ] A documented DuckDB query reads every observation file from the public bucket without credentials
- [ ] The GeoParquet cross-reader check runs in CI with a reader that is installed

## Implementation Plan

## Findings from the worktree (verified)

- `infra/main.tf` `public_read` policy grants only `s3:GetObject` on `${bucket.arn}/*`. `tests/test_infra.py::test_public_read_policy_is_anonymous_getobject_only` asserts exactly one statement and forbids the strings `s3:ListBucket`, `s3:PutObject`, `s3:DeleteObject`, `s3:*`. A DuckDB `s3://` glob issues ListObjectsV2 (with the non-wildcard prefix, e.g. `observations/`), so it fails anonymously. `read_parquet` only accepts a constant path or list, so a "read the file list from a manifest" route would need two queries and is not a one-query path. The story's `touches` (infra/main.tf, tests/test_infra.py) confirms the intended fix is a prefix-scoped anonymous list grant.
- `README.md` "Querying with DuckDB" (line 224) has one ```sql block, which `tests/test_readme.py::test_readme_duckdb_query_returns_rows` extracts with `re.search` (first block only) and runs against local outputs. It must stay first and unchanged. The S3 variant is one prose sentence and says nothing about anonymous access. README line 134 (matrix row GeoParquet output) says "the GDAL read skips when the GDAL build has no Parquet driver".
- `tests/test_geoparquet.py::test_gdal_reads_file_when_parquet_driver_present` skips everywhere: installed pyogrio 0.13.0 (GDAL 3.12.4) lists no Parquet or Arrow driver (checked). Installed readers that do work: duckdb 2.0.0 (native Parquet reader, `bbox` struct), pyarrow 26 (raw Parquet and the `geo` metadata), geopandas `read_parquet` (decodes WKB). The design matrix requires "row counts and bounds agree across readers".
- No bucket exists yet (README Limitations), so the anonymous S3 path cannot be tested end to end in this story. Live tests are `@pytest.mark.live` and excluded by default (`addopts = -m 'not live'`).

## Steps

1. Infra policy (`infra/main.tf`). Add a second statement to `data "aws_iam_policy_document" "public_read"`: sid `PublicListObservationAndChangePrefixes`, Allow, actions `["s3:ListBucket"]`, resources `[aws_s3_bucket.outputs.arn]`, principals `*`, with a `condition` block `test = "StringLike"`, `variable = "s3:prefix"`, `values = ["observations/*", "changes/*"]`. Everything else in the bucket (ledger, runs, stac, verification) stays unlistable. Update the comment above the policy to say why. The `GetObject` statement is unchanged. Do not change the pipeline role.
2. Infra tests (`tests/test_infra.py`). Rewrite `test_public_read_policy_is_anonymous_getobject_only` into `test_public_read_policy_is_getobject_plus_prefix_scoped_list`. It proves: exactly two statements; one is GetObject on the object ARN only; the other is `s3:ListBucket` on the bucket ARN only, carrying a `StringLike` `s3:prefix` condition whose values are exactly `observations/*` and `changes/*`; every statement has `identifiers = ["*"]`; none of `s3:PutObject`, `s3:DeleteObject`, `s3:*` appears; `s3:ListBucket` appears only in the conditioned statement (an unconditioned public list would expose `ledger/` and `runs/`).
3. Docs, infra (`infra/README.md`). Update the "What the module creates" bullet and the Notes bullet: anonymous callers get `s3:GetObject` and `s3:ListBucket` limited to the `observations/` and `changes/` prefixes; no public put or delete. Note that the new list grant needs an apply before the README query works.
4. Docs, root (`README.md`). (a) In "Querying with DuckDB", keep the first local ```sql block byte-for-byte. Replace the single S3 sentence with an "Anonymous query against the public bucket" paragraph and a second ```sql block (placed after the first) that needs no credentials: `INSTALL httpfs; LOAD httpfs;`, `CREATE OR REPLACE SECRET public_outputs (TYPE s3, PROVIDER config, REGION '<aws_region>');` (no key id or secret), then the same SELECT as the local block over `read_parquet('s3://<bucket>/observations/*/*/*.parquet', hive_partitioning = true)`. Say that listing is allowed only under `observations/` and `changes/`, that `changes/` uses the same layout, and that a glob rooted anywhere else is denied. (c) Add a Limitations bullet: the anonymous S3 query has not been run against a real bucket because none is applied; it needs `tofu apply` of the list statement first.
5. README/infra consistency test (`tests/test_readme.py`). Add `test_readme_anonymous_s3_query_matches_public_list_policy`: take the second ```sql block of the "Querying with DuckDB" section; assert it contains `LOAD httpfs`, `hive_partitioning = true`, no `KEY_ID` or `SECRET` credential arguments, and an `s3://<bucket>/<prefix>/` glob whose first path segment is in the allowed `s3:prefix` values parsed from `infra/main.tf` (so README and policy cannot drift apart). ## Orchestrator amendments

- The anonymous list grant covers `observations/*` only, not `changes/*`. The story and design success criterion 3 ask only for observations, and the policy stays least-privilege. Every reference to `changes/` in the steps above is dropped: the statement sid is `PublicListObservationPrefix`, the test pins values exactly `["observations/*"]`, and the docs state that a glob rooted anywhere else, including `changes/`, is denied.
- `terraform init` and `validate` run on a temporary copy of `infra/`, so no `.terraform` directory or lock file change lands in the worktree. Never `plan` or `apply`.
- The design matrix names GDAL as a reader. The new test uses DuckDB and Arrow (pyarrow and geopandas, which share Arrow's Parquet reader). The README row states that GDAL is not exercised because the pinned pyogrio wheel has no Parquet driver.
- The manual check against a public bucket proves that DuckDB globs anonymously. It does not prove the `s3:prefix` condition, which only the live test can check after an apply.
